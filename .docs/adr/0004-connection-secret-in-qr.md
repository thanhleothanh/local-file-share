# 4. Connection Secret in QR Codes

**Status**: Accepted  
**Date**: 2026-05-31

## Context

We need to ensure that only intended devices can connect to each other. With a two-QR handshake, we need a way to authenticate that the two QRs belong to the same connection attempt and that both parties are authorized.

## Decision

Include a **randomly generated connection secret** in both QR codes. The secret is:
- Generated by Device A (initiator) when creating QR #1
- Included in QR #1
- Used by Device B when creating QR #2 (same secret)
- Verified by Device A when scanning QR #2

This ensures:
1. QR #2 is a response to the correct QR #1 (via matching connection ID)
2. Both devices are participating in the same connection attempt (via matching secret)

## Consequences

**Positive:**
- Simple to implement
- No pre-shared team password needed
- Each connection has unique authentication
- Prevents accidental cross-connection between different connection attempts

**Negative:**
- Secret is visible in QR code — anyone who sees QR #1 knows the secret
- No team-wide authentication (each connection is independent)
- If QR #1 is intercepted, the secret is compromised

## Alternatives Considered

1. **Team Shared Secret**: Pre-agreed password for all team members. Pros: Team-wide auth. Cons: Requires manual entry, secret could be leaked.
2. **Manual Entry**: User enters secret after scanning QR. Pros: More secure. Cons: Extra UX step.
3. **Public Key Cryptography**: Use key exchange. Pros: More secure. Cons: Complex to implement in browser.
4. **No Authentication**: Trust anyone who scans. Pros: Simplest. Cons: No security.
